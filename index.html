A1 · Computer fundamentals

Paper 1 · SL 11 hours / HL 18 hours · Hardware, data representation, logic, operating systems and (HL) translation.

What the syllabus expects

CodeTopicSLHL extra
A1.1Computer hardware and operation: CPU components, buses, fetch–decode–execute, memory hierarchy, secondary storage, compression, cloud services✔CPU vs GPU comparison, pipelining in multi-core systems
A1.2Data representation and computer logic: binary/hex/two's complement, how binary stores text, images and sound, logic gates, truth tables, logic diagrams✔—
A1.3Operating systems and control systems: role and functions of the OS, scheduling, polling vs interrupts✔Multitasking, deadlock, control systems (sensor → controller → actuator)
A1.4Translation: compilers vs interpreters—HL only: evaluating compilers, interpreters, bytecode + JIT

Key ideas in one screen

  • The CPU is the ALU, the control unit and registers, joined by the address, data and control buses. The PC holds the address of the next instruction; MAR holds an address; MDR holds data; IR holds the current instruction.
  • Fetch–decode–execute: PC → MAR → address bus → memory returns instruction on data bus → MDR → IR; PC increments during fetch.
  • Cache works because of locality of reference: a hit is fast, a miss stalls the CPU while data comes from RAM.
  • Storage: SSD is fast and robust but costly per GB; HDD is slow, cheap and large; eMMC is cheap and embedded. Match the choice to the scenario's dominant requirement.
  • Compression: lossless (RLE, ZIP, PNG) is perfectly reversible; lossy (JPEG, MP3) permanently discards data people barely notice. RLE makes files bigger when there are no runs.
  • Cloud: IaaS — you manage the OS upward; PaaS — you manage only your application; SaaS — you manage nothing.
  • Data representation: convert binary ↔ hex through 4-bit nibbles; two's complement = invert bits and add 1; image size = width × height × colour depth ÷ 8.
  • Logic: seven gates; a bubble on a gate symbol means inversion; a truth table with n inputs needs 2ⁿ rows and intermediate columns; De Morgan lets you break the bar and change the sign.
  • OS functions: memory, file system, device, scheduling, security, accounting, user interface, virtualisation, networking. FCFS is simple but suffers the convoy effect; round robin is fair but pays switching overhead; priority is efficient but can starve low-priority jobs.
  • Polling suits frequent, predictable events; interrupts save power and suit rare, unpredictable ones.
  • HL: CPU optimises latency, GPU optimises throughput; pipelining overlaps fetch/decode/execute/write-back but hazards limit the gain; deadlock needs all four Coffman conditions; compilers are fast but not portable, interpreters are portable but slow, bytecode + JIT is the modern compromise.

Exam tips for A1

  • Show every step of a conversion. A wrong final answer with correct working still earns method marks; a bare wrong number earns nothing.
  • File-size calculations: pixels × bits → bits ÷ 8 → bytes → MB. State units at every line.
  • For truth tables, write out the intermediate columns (e.g. A XOR B, NOT C) before the final output — they carry marks.
  • Scheduling questions want the trade-off: name the algorithm's advantage and its characteristic weakness (convoy effect, starvation, switching overhead).
  • Polling vs interrupts questions are almost always “evaluate” — relate to the scenario (battery life, event frequency) and finish with a judgement.
  • HL translation questions: compare on speed, portability, error detection and protection of source code, then conclude for the scenario given.

Practice questions

1State the register that holds the address of the next instruction to be fetched.1 mark
Mark-scheme notes. Program Counter (PC).
2Describe the fetch stage of the fetch–decode–execute cycle, with reference to registers and buses.4 marks
Mark-scheme notes. One mark each (max 4): PC copied to MAR; address sent along the address bus; read signal on the control bus; instruction returned on the data bus into MDR; copied from MDR to IR; PC incremented.
3Explain why a cache miss reduces CPU performance.3 marks
Mark-scheme notes. Requested data is not in cache [1]; it must be fetched from a slower level such as RAM [1]; that takes many more clock cycles during which the CPU stalls [1].
4Convert the binary number 11010110 to (a) decimal and (b) hexadecimal.3 marks
Mark-scheme notes. (a) 128+64+16+4+2 = 214 [1]. (b) Split into nibbles 1101 0110 → D and 6 → D6 [1 for nibbling, 1 for digits].
5A photograph is 800 × 600 pixels with a colour depth of 24 bits. Calculate the uncompressed file size in megabytes.3 marks
Mark-scheme notes. 800 × 600 = 480,000 pixels [1]; × 24 = 11,520,000 bits [1]; ÷ 8 = 1,440,000 bytes ≈ 1.44 MB (1.37 MiB) [1].
6Explain why run-length encoding may increase the size of some files.2 marks
Mark-scheme notes. RLE stores each run as a count plus a value [1]; with few or no repeated consecutive values each single symbol becomes two symbols, so the output is larger [1].
7Construct a truth table for Q = (A XOR B) AND (NOT C).4 marks
Mark-scheme notes. 8 rows in correct binary order [1]; correct A XOR B column [1]; correct NOT C column [1]; Q = 1 only when A≠B and C=0, i.e. rows 010 and 100 [1].
8Compare round robin and priority scheduling.4 marks
Mark-scheme notes. Each point must mention both: RR gives every process an equal time slice so it is fair and responsive, whereas priority runs the most important job first; RR pays context-switch overhead, whereas priority risks starvation of low-priority processes; RR is predictable, priority is efficient for real-time work; both are pre-emptive.
9A wireless doorbell runs on a small battery. Evaluate the use of polling versus interrupt handling for detecting the button press.6 marks
Mark-scheme notes. Up to 4 for analysis, 2 for a justified conclusion. Presses are rare and unpredictable; polling wakes the CPU constantly and drains the battery; interrupts let the device sleep and respond immediately; polling is simpler and deterministic but wasteful here. Conclusion: interrupts.
10Explain how pipelining improves performance, and identify one factor that prevents the full theoretical speedup.5 marks
Mark-scheme notes. Stages (fetch, decode, execute, write-back) overlap so several instructions are in flight at once [1–2]; throughput approaches one instruction per cycle [1]; limited by hazards — data dependencies, branch mispredictions requiring a pipeline flush, or resource conflicts [1–2].
11Explain, with reference to the Coffman conditions, how deadlock can arise between two processes, and describe one method of preventing it.6 marks
Mark-scheme notes. Mutual exclusion, hold-and-wait, no pre-emption and circular wait must all hold [up to 4 with an example of P1 holding R1 wanting R2 while P2 holds R2 wanting R1]; prevention removes one condition — e.g. impose a global ordering on resource acquisition to break circular wait, or require all resources to be requested at once [2].

A2 · Networks

Paper 1 · SL 11 hours / HL 18 hours · Fundamentals, architecture, data transmission and security.

What the syllabus expects

CodeTopicSLHL extra
A2.1Network fundamentals: PAN/LAN/WAN/VPN, digital infrastructure, devices (NIC, switch, router, WAP, modem, gateway, firewall), transport and application protocols (TCP, UDP, HTTP/S, DHCP, DNS…)✔The TCP/IP model and encapsulation
A2.2Network architecture: topologies (star, mesh, hybrid…), client–server vs peer-to-peer, segmentation (subnets, VLANs)✔Types of server
A2.3Data transmission: IPv4/IPv6 addressing, NAT, transmission media, packet switching✔Static vs dynamic routing
A2.4Network security: firewalls, encryption, digital certificates✔Common vulnerabilities and countermeasures

Key ideas in one screen

  • PAN (metres), LAN (one site, owned), WAN (wide area, leased infrastructure), VPN (encrypted tunnel over public infrastructure). The Internet is not the World Wide Web.
  • Link-layer devices (NIC, switch, WAP) use MAC addresses; internet-layer devices (router, gateway) use IP addresses; a modem converts digital ↔ analogue; a firewall filters.
  • TCP is reliable, ordered and connection-based (handshake) but slower; UDP is fast with no guarantees — used for live streaming, gaming and VoIP. HTTPS = HTTP + TLS gives confidentiality, integrity and authentication. DHCP uses Discover–Offer–Request–Acknowledge.
  • Star: cheap and simple, central switch is a single point of failure. Full mesh: redundant and reliable but needs n(n−1)/2 links. Real networks are hybrids.
  • Client–server: central control and security, but a single point of failure. P2P: resilient and scalable, but weak security and administration.
  • Subnets work at layer 3, VLANs at layer 2; both shrink broadcast domains (performance) and contain breaches (security).
  • IPv4 is 32-bit, IPv6 is 128-bit. Private address ranges are not routable; NAT lets many private devices share one public address — but NAT is not a firewall.
  • Media: fibre is fast, long-range, secure and expensive; twisted pair is cheap with a 100 m limit and EMI susceptibility; wireless is mobile and convenient but least secure and least reliable.
  • Packet switching: split into packets with headers and sequence numbers, route independently, reassemble at the destination; efficient and resilient but introduces jitter and possible loss.
  • Security: firewalls are necessary but not sufficient (they cannot inspect encrypted traffic or stop social engineering). Symmetric encryption is fast but has a key-distribution problem; asymmetric solves distribution but is slow; real systems use both. Certificates bind a public key to a verified identity and defeat man-in-the-middle attacks.

  • Isaac CS – NetworkingTopologies, protocols, packet switching and security with self-marking questions.

Exam tips for A2

  • When asked to compare devices or protocols, put both items in every sentence (“a switch forwards by MAC address within one network, whereas a router forwards by IP address between networks”).
  • Topology questions are scenario-based: count the nodes, mention cost, single point of failure, redundancy and ease of adding devices, then conclude.
  • Never write “NAT makes the network secure”. Say it conserves public addresses and hides internal addresses, and that security comes from the firewall.
  • For encryption questions, name the problem each type solves: symmetric = speed, asymmetric = key distribution, certificate = identity.
  • “Discuss the effectiveness of a firewall” (8 marks) wants what it does well, what it cannot do, and a balanced conclusion recommending it as part of layered security.
  • HL: the TCP/IP model has four layers (application, transport, internet, link); explain encapsulation as each layer adding its own header on the way down.

Practice questions

1Describe two differences between a LAN and a WAN.2 marks
Mark-scheme notes. Any two: geographic scale; ownership (LAN owned by the organisation, WAN uses leased carrier links); bandwidth; latency; cost.
2Explain why UDP rather than TCP is used for live video streaming.3 marks
Mark-scheme notes. No acknowledgements or retransmission, so lower latency and overhead [1]; a late packet is useless because its moment has passed [1]; better to drop it than stall the stream waiting for a retransmission [1].
3Describe the function of a router and explain how it differs from a switch.4 marks
Mark-scheme notes. Router connects different networks [1] and forwards packets using destination IP addresses and a routing table [1]; a switch works inside one network [1] forwarding frames by MAC address to the correct port only [1].
4A school is choosing between a star and a mesh topology for a new lab of 30 machines. Discuss which is more appropriate.6 marks
Mark-scheme notes. Up to 4 analysis, 2 conclusion. Star: cheap, simple, easy fault isolation, but central switch is a single point of failure. Mesh: no single point of failure, but 30 nodes need 435 links — prohibitively expensive and complex. Conclusion: star, possibly with a spare switch.
5Explain the role of NAT in a home network.4 marks
Mark-scheme notes. Many devices share one public IPv4 address [1]; router rewrites source address/port on outgoing packets and keeps a translation table [1]; replies are mapped back to the correct private device [1]; conserves public addresses and hides internal addressing, though it is not itself a firewall [1].
6Explain how packet switching allows data to be transmitted reliably across a network.5 marks
Mark-scheme notes. Message split into packets [1]; each has a header with addresses and a sequence number [1]; packets take independent routes around congestion or failed links [1]; destination reassembles them in order [1]; missing packets are detected and re-requested (TCP) [1].
7Explain the difference between symmetric and asymmetric cryptography, and describe why HTTPS uses both.6 marks
Mark-scheme notes. Symmetric: one shared key, fast, but the key must be exchanged securely [2]; asymmetric: public/private key pair, solves distribution, but is computationally slow [2]; HTTPS uses asymmetric during the TLS handshake to agree a session key, then symmetric for the bulk data [2].
8Describe the four layers of the TCP/IP model and explain the role of encapsulation.6 marks
Mark-scheme notes. Application (HTTP, DNS, SMTP) [1]; transport (TCP/UDP, ports, reliability) [1]; internet (IP addressing and routing) [1]; link (MAC addressing, physical transmission) [1]; encapsulation adds each layer's header on the way down and strips it on the way up, so each layer only needs to understand its own header [2].
9Describe three common network vulnerabilities and identify an appropriate countermeasure for each.6 marks
Mark-scheme notes. Two marks per pair, e.g. phishing → user training and email filtering; unpatched software → patch management; weak passwords → MFA and password policy; SQL injection → parameterised queries and input validation; DDoS → traffic filtering/CDN; man-in-the-middle → TLS and certificates.

A3 · Databases

Paper 1 · SL 11 hours / HL 18 hours · Relational design, normalisation, SQL and (HL) alternative databases.

What the syllabus expects

CodeTopicSLHL extra
A3.1Database fundamentals: features, benefits and limitations of relational databases✔—
A3.2Database design: schemas, ERDs, data types, constructing tables, normal forms to 3NF, denormalisation✔—
A3.3Database programming: DDL vs DML, SELECT with JOIN/WHERE/ORDER BY, INSERT/UPDATE/DELETE✔Aggregate functions, GROUP BY/HAVING, views, transactions (ACID)
A3.4Alternative databases and data warehouses—HL only: NoSQL, cloud, spatial and in-memory databases; data warehouses; OLAP and data mining; distributed databases (CAP)

Key ideas in one screen

  • Tables, rows, columns. A primary key uniquely identifies a row; a foreign key references another table's primary key; a many-to-many relationship always needs a junction table; the FK sits on the “many” side of a 1:M.
  • Benefits: less duplication, consistency, integrity via constraints, concurrent access, ACID transactions, security, ad hoc querying. Limitations: rigid schema, design effort, weak horizontal scaling, poor fit for unstructured or hierarchical data.
  • Three schemas: conceptual (what — ERD), logical (how structured — tables, types, keys), physical (how stored — indexes, files).
  • ERD crow's foot: inner symbol = modality (○ optional, | mandatory); outer symbol = cardinality (| one, crow's foot many).
  • Normalisation: 1NF atomic values; 2NF no partial dependencies on part of a composite key; 3NF no transitive dependencies. “The key, the whole key and nothing but the key.” It removes insertion, update and deletion anomalies.
  • Denormalisation trades integrity for read speed — justified for read-heavy reporting. Normalise first, denormalise deliberately.
  • SQL clause order: SELECT – FROM – JOIN – WHERE – GROUP BY – HAVING – ORDER BY. WHERE filters rows before grouping; HAVING filters groups after. UPDATE or DELETE without WHERE affects every row. Indexes speed reads and slow writes.
  • HL: aggregates ignore NULL except COUNT(*); virtual views are live but slow, materialised views are fast but stale; ACID = atomicity, consistency, isolation, durability with BEGIN/COMMIT/ROLLBACK; data warehouses are subject-oriented, integrated, time-variant, non-volatile; OLAP is hypothesis-driven, data mining is discovery-driven; distributed databases face the CAP trade-off.

Exam tips for A3

  • In a normalisation question, show each stage: identify the key, list dependencies, then write the final tables with PKs underlined and FKs marked (*). The table list carries most of the marks.
  • Always resolve many-to-many relationships with a junction table whose primary key is usually composite.
  • Write SQL keywords in capitals, quote strings, and check every JOIN has an ON condition matching FK = PK. Sort with ORDER BY last.
  • “Explain why storing X as INT is a problem” questions want concrete consequences: leading zeros lost, characters rejected, no meaningful arithmetic.
  • Denormalisation and NoSQL questions are “evaluate/discuss”: give the workload (read-heavy? varied structure? huge scale?), both sides, and a conditional conclusion.
  • HL: for ACID, use a bank-transfer example and tie each property to one line of the story.

Practice questions

1Define the terms primary key and foreign key.2 marks
Mark-scheme notes. PK: attribute(s) uniquely identifying each row, unique and never NULL [1]. FK: attribute in one table referencing the PK of another, creating a relationship [1].
2Explain why a many-to-many relationship cannot be implemented directly in a relational database, and describe how it is resolved.4 marks
Mark-scheme notes. A field can hold only one value [1], so M:N would need multiple FK values in one field, breaking 1NF [1]; resolve with a junction table [1] holding FKs to both tables (usually a composite PK), giving two 1:M relationships [1].
3A table stores phone numbers as INT. Explain two problems this causes.4 marks
Mark-scheme notes. Any two, 2 marks each: leading zeros stripped; characters such as +, spaces and hyphens cannot be stored; long international numbers may overflow; arithmetic on a phone number is meaningless so the numeric type gives no benefit.
4The table Booking(BookingID, GuestName, GuestPhone, RoomNumber, RoomType, RatePerNight, CheckIn, Nights) is in 1NF. Normalise it to 3NF, showing each stage.8 marks
Mark-scheme notes. Single-attribute PK so already 2NF [1]; transitive dependencies: BookingID→GuestName→GuestPhone and BookingID→RoomNumber→RoomType→RatePerNight [2]; 3NF: Guest(GuestID, GuestName, GuestPhone), RoomType(RoomTypeID, TypeName, RatePerNight), Room(RoomNumber, RoomTypeID*), Booking(BookingID, GuestID*, RoomNumber*, CheckIn, Nights) [up to 5].
5Explain the difference between the WHERE and HAVING clauses.3 marks
Mark-scheme notes. WHERE filters individual rows before grouping [1]; HAVING filters groups after GROUP BY, so it can use aggregates [1]; e.g. WHERE grade > 4 vs HAVING COUNT(*) > 10 [1].
6Using Student(StudentID, Surname, YearGroup), Enrolment(StudentID*, CourseID*, Grade), Course(CourseID, CourseName, Department), write SQL to list the surname and course name of every Year 12 student taking a Science course, sorted by surname.5 marks
Mark-scheme notes. SELECT Surname, CourseName FROM Student JOIN Enrolment ON Student.StudentID = Enrolment.StudentID JOIN Course ON Enrolment.CourseID = Course.CourseID WHERE YearGroup = 12 AND Department = 'Science' ORDER BY Surname; [marks for SELECT list, both JOINs with correct ON, WHERE with both conditions, ORDER BY].
7Evaluate the decision to denormalise a database used for a reporting dashboard.6 marks
Mark-scheme notes. For: fewer joins so faster reads; dashboards are read-heavy; simpler queries. Against: redundancy, update anomalies, larger storage, harder to keep consistent. Conclusion: justified for the reporting copy if the transactional database stays normalised (or a materialised view is used).
8Explain, with an example, how the ACID properties ensure data integrity during a bank transfer.6 marks
Mark-scheme notes. Example: deduct £100 from A and add to B [1]; atomicity — both or neither [1]; consistency — total money unchanged and constraints hold [1]; isolation — a concurrent balance query never sees the half-done state [1]; durability — once committed the change survives a crash [1]; achieved with BEGIN/COMMIT/ROLLBACK [1].
9A social media company must store user posts of widely varying structure at massive scale. Discuss whether a relational or NoSQL database is more appropriate.8 marks
Mark-scheme notes. Relational: integrity, ACID, powerful joins, but rigid schema and poor horizontal scaling. NoSQL (document store): flexible schema, scales out across servers, high availability, but eventual consistency and weaker joins. Conclusion: NoSQL for posts, possibly relational for accounts/billing — a polyglot approach.

A4 · Machine learning

Paper 1 · SL 5 hours / HL 18 hours · Fundamentals and ethics for all; preprocessing and ML approaches for HL.

What the syllabus expects

CodeTopicSLHL extra
A4.1ML fundamentals: supervised, unsupervised, reinforcement, deep and transfer learning; hardware for training and inference (CPU, GPU, TPU, FPGA, edge, cloud)✔—
A4.2Data preprocessing: cleaning, missing data, normalisation, feature selection, dimensionality reduction—HL only
A4.3ML approaches: linear regression, classification (k-NN, decision trees), evaluation metrics, clustering, association rules, reinforcement learning, genetic algorithms, neural networks and CNNs, model selection—HL only
A4.4Ethical considerations: bias, fairness, transparency, consent, inference, environmental impact; ethics of computing in daily life✔—

Key ideas in one screen

  • Supervised = labelled data, predicts a label (classification) or a value (regression). Unsupervised = unlabelled data, finds structure (clustering, association). Reinforcement = agent, environment, reward, policy. Deep learning = many-layered networks that learn features automatically. Transfer learning reuses a pretrained model and fine-tunes it on a small dataset.
  • Training is heavy, inference is light. GPU is the mainstream training choice (thousands of parallel cores, high memory bandwidth); TPU/ASIC gives maximum efficiency at scale with no flexibility; FPGA is the reconfigurable middle ground; edge devices give low-latency, private local inference; cloud gives elastic capacity.
  • HL preprocessing: garbage in, garbage out. Handle outliers, duplicates, bad formats; missing data by deletion, imputation or prediction (each with its own bias risk). Normalise for any distance-based algorithm. Feature selection: filter (fast), wrapper (accurate, expensive), embedded (compromise). Curse of dimensionality: sparsity and breakdown of distance metrics.
  • HL approaches: linear regression (slope, r²; correlation ≠ causation); k-NN (small k overfits, large k underfits; needs scaling); decision trees (interpretable but overfit — prune or use forests); precision = trust the yes, recall = catch everything, F1 balances them, accuracy misleads on imbalanced data; association rules need lift > 1; RL balances exploration and exploitation; genetic algorithms use selection, crossover and mutation (mutation escapes local optima); perceptron = inputs, weights, bias, activation; CNNs use shared kernels for translation invariance and pooling to downsample.
  • Ethics: bias comes from data that reflects an unequal world; fairness definitions conflict; black-box models obstruct accountability; consent is often fictional at scale; inference reveals facts never disclosed; environmental costs (and benefits) are real. Structure every ethics answer: context, named issues, both sides, mitigations, conclusion.

Exam tips for A4

  • Every “describe an application” answer must name the type of learning and say why (labelled data? reward signal?).
  • Hardware questions are scenario questions: ask whether it is training or inference, whether latency matters, whether data can leave the site, then justify.
  • HL: if a question mentions accuracy on a rare event, immediately suspect class imbalance and bring in precision, recall and F1.
  • HL: normalise before k-NN or k-means — say why (large-magnitude features dominate the distance).
  • Ethics (8 marks): specific context → at least three named issues (bias, transparency, consent, accountability) → mitigation for each → balanced conclusion. Generic answers cap at half marks.
  • Link A4.4 to the case study: the 2027 case study is about generative image AI, so bias in training data, consent of artists and environmental cost are likely Section B territory.

Practice questions

1Distinguish between supervised and unsupervised learning.3 marks
Mark-scheme notes. Supervised uses labelled data and learns input→output mapping [1]; unsupervised uses unlabelled data and finds structure [1]; so supervised predicts a known target while unsupervised discovers groupings not defined in advance [1].
2Describe two real-world applications of machine learning, identifying the type used in each.4 marks
Mark-scheme notes. 1 for the application + 1 for the type, twice. E.g. medical scan diagnosis — supervised deep learning; customer segmentation — unsupervised clustering; robot navigation — reinforcement learning; market-basket analysis — association rules.
3Explain why GPUs are more suitable than CPUs for training neural networks.4 marks

Key ideas in one screen

  • Python is dynamically typed; input() always returns a string, so convert with int() or float(). Local vs global scope. Short-circuit evaluation of and/or.
  • Validation types: range, type, length, presence, format, lookup, consistency. Good validation re-prompts and explains the problem.
  • Errors: syntax (caught before running), run-time (crash during execution, e.g. ZeroDivisionError, IndexError), logic (runs but gives the wrong answer — the dangerous one). Test with normal, boundary and erroneous data.
  • Lists give O(1) index access and grow dynamically; dictionaries give O(1) lookup by key; sets give uniqueness and fast membership. Valid indices run from 0 to length−1.
  • Order selection conditions from most to least restrictive. A while loop may run zero times. range(n) gives 0 to n−1.
  • Functions: reusability, decomposition, maintainability, readability, testability. Parameters sit in the definition, arguments at the call.
  • Complexity ladder: O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ).
  • Linear search O(n), no sorting needed; binary search O(log n) but requires sorted data. Bubble sort O(n²) with O(n) best case using a swapped flag, stable; selection sort always O(n²), few swaps, not stable; insertion sort O(n²) but O(n) on nearly sorted data, stable.
  • HL recursion: base case + recursive case; uses O(depth) stack space; naive Fibonacci is O(2ⁿ); best suited to trees and divide-and-conquer.
  • Files: mode 'w' overwrites, 'a' appends, 'r' reads; use with open(...); write() does not add a newline; handle FileNotFoundError and malformed lines.
  • Static vs dynamic data structures — a static structure has a fixed size set when it is created (a classic array); a dynamic one can grow and shrink while the program runs (a Python list, a linked list).
  • Stack — LIFO. push, pop, peek, isEmpty all O(1); one pointer (top, −1 when empty). Underflow on empty pop, overflow on full push. Uses: call stack, undo, bracket matching, backtracking, reversal.
  • Queue — FIFO. enqueue at rear, dequeue at front, O(1); two pointers. A circular queue uses modulo arithmetic to reuse vacated slots. Uses: print spooling, CPU scheduling, packet buffers, breadth-first search.

Key ideas in one screen

  • HL: abstract classes cannot be instantiated and force subclasses to implement methods; interfaces define capability contracts.
  • HL UML: + public, − private, # protected; hollow triangle points at the superclass; filled diamond = composition (part dies with the whole); hollow diamond = aggregation (part survives).

Key ideas in one screen

  • An ADT defines the operations and their behaviour, not the implementation. A linked list is an ADT; a node-and-pointer structure is an implementation. This is abstraction applied to data.
  • Linked list — nodes with data plus a pointer to the next node. Dynamic size and O(1) insertion at the head, but O(n) access by position and poor cache performance. When inserting, set the new node's pointer before redirecting the previous node's.
  • Binary search tree — left subtree smaller, right subtree larger. O(log n) search/insert/delete when balanced; degrades to O(n) if built from sorted input.
  • Traversals: in-order (L, N, R) gives sorted order; pre-order (N, L, R) copies a tree; post-order (L, R, N) deletes a tree.
  • Set — a collection of unique items with no required order. Key operations: add, remove, membership test, union, intersection and difference; A is a subset of B if every item of A is in B.
  • Hash table — a hash function turns a key into an index, so a value can usually be found without searching: average O(1) lookup, insertion and deletion. Two keys can hash to the same index (a collision), which the implementation must handle, for example by chaining or probing. Python's dict and set and Java's HashMap and HashSet are hash tables.
  • Stacks and queues are core content in B2.2 (SL and HL) — see the B2 page.

Internal Assessment · The computational solution

30% at SL, 20% at HL · 35 hours · 30 marks · ≤2,000 words · mandatory video (max 5 minutes).

The IA is marked on the documentation of a development process, not on how impressive the program is. A modest program that is well specified, planned, tested and honestly evaluated beats a spectacular program with thin documentation — every time.

Choosing a problem

  • Solvable in roughly 20 hours of coding — not 5, not 100.
  • Clear input → process → output structure, with data that persists in files.
  • Natural complexity: searching, sorting, validating, calculating, relating several entities.
  • Objectively testable — you can state what the right answer is.
  • Interesting enough to hold your attention for 35 hours. There is no client requirement any more; pick a problem you actually care about.

Criterion D — the structure that works

  • Name the technique (e.g. “insertion into a dictionary with a uniqueness check”).
  • Show a focused, commented code extract — not the whole file.
  • Explain how it works, step by step.
  • Justify why you chose it over the alternatives, against a specific requirement.
  • Note a difficulty and how you resolved it.
  • Techniques that count: searching/sorting you wrote yourself, non-trivial data structures (ADTs at HL), file handling with error recovery, comprehensive validation, OOP design (inheritance/polymorphism at HL), recursion where genuinely appropriate, multi-condition aggregation, parameterised sub-programs, algorithms with a real complexity argument.
  • Techniques that do not count: printing, arithmetic, a single if, a counting loop, or a built-in that does the whole interesting job.
  • Comment the why, not the what.

Criterion E — be honest

Work through every success criterion by number with evidence (test IDs, video timestamps). Examiners can read your code and watch your video; an honest “partially met” scores better than an inflated claim. Improvements must be specific and follow from your own identified shortcomings — “replace the CSV with SQLite to enforce data types at the storage layer”, not “store data better”.

The video

  • Screen recording of no more than 5 minutes, showing the product working and examples of testing.
  • Demonstrate each success criterion in turn, narrated or captioned.
  • Show failures being handled — invalid input rejected, missing file recovered — not only the happy path.
  • Reference timestamps in your Criterion E table.

The case study is a pre-seen scenario released about twelve months before the May session. You do not get the document in the exam. Section B rewards two things: understanding the specific technologies it names (including ones outside the syllabus) and applying syllabus knowledge to that scenario rather than answering generically. A six-step method (start the week it is released)

  • Read it three times: once for the story, once highlighting every technical term, once for the tensions (cost vs performance, privacy vs functionality, reliability vs complexity). Examiners write questions about tensions.
  • Build a glossary of 30–50 entries at four or five a week. For each term: definition, how it works, why it is used in this scenario, advantages, limitations, syllabus link.
  • Map the case study onto the syllabus: one row per sub-topic it touches (for 2027 expect A1.1 GPU/TPU hardware, A1.1 compression and storage, A4.1 deep learning, A4.3 neural networks and CNNs, A4.4 ethics, A2.1 cloud infrastructure, A3.4 large-scale data).
  • Write your own questions using the command terms — explain why X rather than Y (6), discuss the ethical implications (8), evaluate the security/safeguards (8), describe how a named technology operates (4), recommend an improvement (6) — and answer them to time.
  • Research beyond the document: manufacturer documentation, technical overviews, standards summaries. Questions can target these terms directly.
  • Practise applying, not reciting: anchor every point to the organisation, system or data in the scenario.

Exam technique

Turning what you know into marks — command terms, answer structure, Paper 2 habits and the week before.

Most people lose marks they did not need to lose: they answer “explain” as if it said “describe”, or write four marks of material for a two-mark question. Fixing that is worth more than another week of content revision.

The three that cost the most

  • “Explain” answered as “describe”. Test: does every point contain a “because”, “so that” or “which means”? If not, you are describing and capped at about half marks.
  • “Compare” answered as two separate descriptions. Each sentence must reference both items: “Whereas a stack removes from the same end it inserts at, a queue removes from the opposite end.”
  • “Evaluate” with no judgement. Both sides, then a reasoned, ideally conditional, conclusion: “X is preferable where the data is nearly sorted; Y at scale.”

Structure for a 6–8 mark Paper 1 answer

  • One sentence defining or setting out the key concept.
  • Three or four developed points: claim → because → example or consequence.
  • For discuss/evaluate, at least one point on the other side.
  • For evaluate/justify, a conclusion.
  • Read the mark allocation: a 4-mark question wants four developed points. Budget about 1.5 minutes per mark.
  • Top-band answers make synoptic links: cache locality → array performance → arrays vs linked lists; SQL injection → parameterised queries → input validation; abstraction → OS → three-schema architecture → encapsulation → ADTs → TCP/IP layers; recursion → call stack → stack overflow.

Paper 2 technique

  • Underline the exact requirement: return vs print, index vs value, “without built-in functions”.
  • Comment as you go; handle empty input, one element, not found, division by zero.
  • Initialise correctly (a maximum set to 0 fails on negative data); check loop bounds (range(n) is 0 to n−1).
  • Always draw the trace table — it earns marks even if the final answer is wrong.
  • “Explain your choice of data structure”: name it, give its complexity for the operations that matter here, name the alternative, say why it loses.
  • Do not panic over syntax; logic errors are what cost marks. If you forget a method name, write clear pseudocode and state your intent.

Common errors to avoid

  • Confusing validation (is the data reasonable?) with verification (was it entered correctly?).
  • Confusing abstraction with encapsulation; overriding with overloading; composition with aggregation.
  • Saying NAT provides security.
  • Treating a high accuracy figure as proof of a good ML model without checking class imbalance.
  • Forgetting that binary search needs sorted data, or that in-order traversal of a BST gives sorted order.
  • Drawing the UML inheritance triangle pointing at the subclass.
  • Running out of time on Section A and leaving Section B unattempted — it is 12 marks at SL and 24 at HL. Budget for it first.

The week before

  • Work through the key-ideas summaries on every topic page.
  • Re-read your case study glossary and predicted questions.
  • Hand-trace bubble, selection and insertion sort and binary search on small arrays until automatic.
  • Practise drawing: the CPU diagram, a logic circuit and truth table, an ERD, a UML class diagram, a BST with its three traversals.
  • Do one full past-style paper to time, including Section B, in your exam mode (paper or digital).
  • Confirm your Paper 2 language (Python) and exam mode with your coordinator.
